# RGB conformance

The rules of RGB, for both lines (v0.11 and v0.12), as data, with a generated specification and a test suite that runs in your browser.

- **Live suite:** https://rgbjs.github.io/rgb-conformance/
- **Specification:** https://rgbjs.github.io/rgb-conformance/spec.html

An independent community project, not affiliated with RGB-WG, the RGB Protocol Association or LNP/BP. Early work: not for real funds. Modelled on [bitcoin-kernel](https://bitcoin-kernel.com)'s conformance suite for Bitcoin.

## What's here

| Path | What it is |
|---|---|
| `rules/v011.jsonld`, `rules/v012.jsonld` | The rules, in JSON-LD (`rules/context.jsonld`). Each rule is one invariant, with its level (`upstream`, `rgbjs` or `informative`), the upstream error it maps to, and the crate, file and line where that check lives. |
| `vectors/index.json` | 394 vectors, each tagged with the rules it exercises. Generated by `tools/make-vectors.mjs`. |
| `vectors/v011`, `vectors/v012` | The source data: upstream invoice test cases, real CLI invoices, and consignments for v0.11 NIA, CFA, UDA and IFA, and for v0.12 RGB20, RGB21 and RGB25. `SOURCES.md` in each says where every file comes from. |
| `engine/` | A copy of [rgbjs](https://github.com/rgbjs/rgbjs) (version in `engine/VERSION`): each line's Rust crates compiled to WebAssembly. |
| `lib/runner.js` | Runs the vectors against an engine, in Node or a browser. |
| `spec.html` | The specification, generated from the rules by `build.js`. |
| `index.html` | The live suite. |

## How the corruption vectors are made

`tools/make-vectors.mjs` flips one bit in every byte of each consignment, runs the result through the engine, and files the outcome under the rule it breaks. It fails if any corruption is accepted as the same contract with the same result, or if an outcome matches no rule. So every byte of every consignment is accounted for, and up to three corruptions per rule and file are kept as vectors.

## Run it

```sh
tools/refresh.sh /path/to/rgbjs   # pull the engine and vectors from rgbjs, regenerate everything, run the suite
node test.js           # the suite in Node; exits non-zero on any failure
node build.js          # regenerate spec.html (build.js --check verifies it's current)
node tools/make-vectors.mjs   # regenerate vectors/index.json
python3 -I tools/og.py        # regenerate the social cards (needs Pillow)
```

No dependencies beyond Node 18 or later. There's no CI deploy step: run `tools/refresh.sh` by hand when rgbjs changes, review the diff, and commit. To test another implementation, give `lib/runner.js` an engine with `parseInvoice(string)` and `validateConsignment(bytes)` for each line (see the top of that file).

## Conformance levels

- **upstream:** the reference code rejects violations; a conforming implementation must too.
- **rgbjs:** the reference code accepts it, but that is unsafe or misleading. For example, it pre-allocates gigabytes from a forged length, or accepts a genesis that names another codex. Implementations should reject it.
- **informative:** the input can be valid but isn't the original. Implementations may accept it, but their result must show the difference.
